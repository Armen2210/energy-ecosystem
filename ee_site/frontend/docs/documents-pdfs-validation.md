## Результат и исходники

После опросных листов выведены две непустые категории:
«Сертификаты партнёрства» и «Специальная оценка условий труда (СОУТ)».
В первой четыре документа в порядке задания; во второй СОУТ 2026, затем 2022.
Всего три категории, десять логических документов и четырнадцать ссылок.
Другие пустые категории остаются скрытыми.

Для каждого нового документа в реестре один вариант `pdf` с `behavior: open`.
Ссылка «Открыть PDF» содержит размер, формат и предупреждение новой вкладки;
`target=_blank`, `rel=noopener noreferrer`, без download. Восемь вариантов
опросников сохранили скачивание, названия, назначения и прежние байты.

СОУТ имеет подпись «Сводная ведомость результатов и перечень рекомендуемых
мероприятий». Она задаётся обычным полем description логического документа,
без отдельных компонентов сертификатов. Иерархия заголовков H1/H2/H3 и существующее
оформление сохранены. Добавлено только правило подписи под названием документа.
На desktop три белые подложки категорий; на tablet/mobile подложки сняты.
Обложек, миниатюр, отдельных страниц и дополнительных кнопок нет.
SEO-описание самой `/documents` обновлено по фактическому наполнению.

Источник шести PDF — приложения текущего задания владельца:
`Св-во_ЭНЕРГОЭФФЕКТ (1) (1).pdf`, `свидетельство ТТ-к.pdf`,
`ЭНЕРГОЭФФЕКТ (1).pdf`, `сертификат ЭНЕРГОЭФФЕКТ (1).pdf`,
`СОУТ 2026 (1).pdf`, `СОУТ 2022.pdf`.
Оригиналы сохранены в каталоге загруженных файлов вне public и не изменены.
Четыре сертификата скопированы побайтно. Их исходные и опубликованные SHA-256

## Поворот СОУТ без потери содержания и качества

Исходные страницы сканов были боком. Для всех трёх страниц СОУТ 2026 и всех
пяти страниц СОУТ 2022 установлен PDF `/Rotate 270` (90° против часовой стрелки).
Визуально проверены все восемь страниц после поворота: горизонтальное чтение,
сохранность таблиц, подписей и краёв. Растеризация применялась только для
временного контрольного просмотра, не для формирования публичного PDF.

Публичные файлы сохранены incremental-обновлением PyMuPDF. Полная исходная
последовательность байтов осталась неизменным префиксом. Проверено:

- число страниц и xref-объектов не изменилось;
- изменились только словари восьми PDF-страниц с параметром Rotate;
- все 7 raw-потоков СОУТ 2026 и 11 raw-потоков СОУТ 2022 побайтно сохранены;
- MediaBox, CropBox, ссылки на content/image streams и metadata сохранены;
- не выполнялись rescan, сжатие, перекодирование изображений или обрезка.

Исходные файлы вне public:

| Источник | Байт | SHA-256 исходника |
| --- | ---: | --- |
| sout-2026 | 891404 | `910ebc85fc58ad7142bcc2b6f9328e026558fc183cb6cb91022dc600de7d6aa2` |
| sout-2022 | 1710665 | `11e29912bc31a1be3c1f990fd48ba60caa2ff2f9dee0e541523c3bab22e1ea37` |

СОУТ 2022 опубликован по окончательной корректировке владельца в предоставленном
**пятистраничном** составе. Отсутствующие страницы не добавлялись, комплект
не назван полным. Последующая замена описана ниже.

## Точный порядок последующей замены СОУТ 2022

1. Получить от владельца новую версию. Сохранить её исходник и при необходимости
   архив прежнего файла **вне public**. Проверить все предоставленные страницы
   и их порядок; не добавлять страницы самостоятельно. Если они боком, исправить
   только PDF-поворот, без печати в PDF/растеризации/сжатия/обрезки. Текущий способ:
   изменение Rotate с incremental-сохранением, сохранность stream bytes/boxes.
2. Заменить ровно
   **`ee_site/frontend/public/documents/sout/ee-sout-2022.pdf`** итоговым файлом.
   Не создавать новое имя, каталог версии или дополнительную ссылку.
   Публичный URL должен остаться
   **`/documents/sout/ee-sout-2022.pdf`**.
3. Из каталога `ee_site/frontend` вычислить размер и SHA-256 **после** всех
   разрешённых поворотов, по итоговым публичным байтам:

   ```sh
   node --input-type=module -e "import {readFileSync} from 'node:fs'; import {createHash} from 'node:crypto'; const b=readFileSync('public/documents/sout/ee-sout-2022.pdf'); console.log(JSON.stringify({sizeBytes:b.length,sha256:createHash('sha256').update(b).digest('hex')},null,2));"
   ```

4. В **`ee_site/frontend/src/data/documents.js`**, документ **`id: sout-2022`**,
   обновить у единственного варианта **`files[0].sizeBytes`** и
   **`files[0].sha256`**. Оставить `files[0].url`, `behavior: open`, id, название
   и порядок документа без изменения. Дополнить отчёт новой записью о замене
   и её фактических проверках, не выдавая старый hash за новый.
5. Выполнить `npm test`, `npm run lint`, сборку и prerender с одинаково
   выключенной аналитикой:

   ```sh
   VITE_EE_ANALYTICS_ENABLED=false npm run build
   VITE_EE_ANALYTICS_ENABLED=false npm run test:prerender
   ```

   Устаревшие sizeBytes/hash должны вызывать ошибку проверки файла, их нельзя
   обходить. Проверить в отдельном nginx-fixture GET/HEAD прежнего URL:
   **200**, **application/pdf**, Content-Length равен новому sizeBytes,
   SHA-256 полученных GET-байтов равен новому sha256. Проверить реальный 404
   соседнего отсутствующего PDF. Убедиться, что отдаются новые байты, не старая
   закешированная версия.
6. В браузере открыть «Результаты СОУТ — 2022»: та же ссылка, новая вкладка,
   новое значение размера, читаемая правильная ориентация **всех страниц новой
   версии** и сохранность содержания. При отдельном разрешённом внедрении
   использовать полный согласованный dist (HTML/JS/файл вместе).
   Этот отчёт не является разрешением на deploy.
