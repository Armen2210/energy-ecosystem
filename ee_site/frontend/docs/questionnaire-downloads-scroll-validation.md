# Бланки в шапке ОЛ и мобильная прокрутка

Ветка: `feature/ee-documents`. Исходный SHA после fetch из origin:
`7f46fa0998ca885ae2dc86cb27998b5850477fd6`.

## Подтверждённые причины и исправления

- Мобильный `navigate()` вызывал `panel.scrollIntoView({block: "start"})`.
  При исходной позиции панели навигации 179.84 px её верх после нажатия
  оказывался на 323.84 px: скачок 144 px.
- Эффект `QuestionnaireEditor` независимо восстанавливал `window.scrollTo`
  из `pageScroll` при смене изделия/листа и появлении отложенного редактора.
  Поэтому старый черновик БМК перебивал обычный переход страницы наверх:
  в воспроизведении после EntitySwitcher получалось `scrollY=2556`.
  Две команды также возвращали пользователя к позиции, выбранной программой,
  вместо его текущей ручной прокрутки.
- Удалены обе команды и сохранение вертикального `pageScroll` редактором.
  Старые значения допускаются в черновике, но больше не используются для
  перемещения документа. Ответы и остальные данные черновика не мигрируются.
- Локальное действие снимает координату своей навигации/нажатой шапки перед
  обновлением store. `useLayoutEffect` компенсирует только изменение этой
  координаты после коммита. Нет восстановления при mount, таймеров под экран,
  фиксированной мобильной высоты или внутренней вертикальной прокрутки ОЛ.
  Границы прокрутки остаются нативными.
- Обычный переход страницы явно использует `instant`, чтобы не наследовать
  глобальный CSS `scroll-behavior: smooth`. Особые entryScroll, hash,
  документы и caseReturn сохраняют свои ветви. EntitySwitcher не менялся.
- Sticky-навигация измеряет полный border-box настоящей шапки через
  ResizeObserver. Ошибка поля — отдельный явный переход с `preventScroll`
  при фокусировке и учётом шапки/навигации. Запрос фокуса потребляется один
  раз и не повторяется при возвращении в раздел стрелками.

## Скачивание и состояния

Лёгкая `QuestionnaireHeader` находится вне deferred-рендерера полей. Она
присутствует в prerender четырёх продуктовых страниц, при задержке/ошибке
импорта редактора и недоступном backend. URL, форматы и поведение берутся
из `documents.js` по `categoryId` и `productSlug`; копий метаданных нет.

«Заполнить онлайн →» включает и раскрывает текущий ОЛ через прежний store;
переключатель формы синхронизируется. Включённый ОЛ показывает статус.
Онлайн-кнопки учитывают backend и submitting. Download-ссылки независимы
от этих состояний; при направлении без бланков их нет.

Скачивание выключенного/свёрнутого ОЛ не включает и не раскрывает его.
Проверены независимые ответы четырёх ОЛ, общие контакты, сохранение ссылок
на File и submission/UUID, а также indeterminate. Страница «Документы»,
backend, API, миграции, контракт, lockfile и 14 публичных файлов не менялись.

Запуск новой браузерной регрессии из `ee_site/frontend`:

```bash
# Vite должен работать локально; тест перехватывает capabilities и запрещает POST.
QUESTIONNAIRE_TEST_ORIGIN=http://127.0.0.1:5173 \
QUESTIONNAIRE_OUTPUT=/tmp/ee-scroll-downloads \
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
CHROME_PATH=/path/to/chromium \
node scripts/questionnaire-scroll-downloads-browser.mjs
```

Тест использует фактические URL модулей Vite, включая HMR-версии, чтобы
проверять тот же store, что и приложение. В production bundle тестовых
hooks нет. Скриншоты и подробные JSON/log этой сессии находятся в
`/workspace/ee-documents-evidence`: `desktop-1440.png`, `desktop-1366.png`,
`mobile-360-collapsed.png`, `mobile-390-expanded.png`, `text-200-*.png`,
`before.json`, `geometry.json`, `scroll-results.json` и результаты прежних suites.

Ограничения: Chromium/Linux, мобильный viewport и touch emulation.
Изменение доступной высоты при клавиатуре моделировалось resize; физические
iOS/Android и Safari не запускались. API capabilities в браузерных сценариях
синтетические; реальный SMTP не использовался. Это локальная проверка,
без deployment и без изменений main/production.
