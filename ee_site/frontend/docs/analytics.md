# Аналитика сайта Энергоэффект

## Запуск и отказ

В production на HTTPS-доменах energoeffekt-rostov.ru и www.energoeffekt-rostov.ru
Яндекс Метрика запускается при первом посещении, если включён флаг сборки
VITE_EE_ANALYTICS_ENABLED=true и в браузере нет действующего отказа.
Calltouch q0fhtb2e дополнительно требует VITE_EE_CALLTOUCH_ENABLED=true.
Оба флага по умолчанию выключены; localhost и preview-домены не отслеживаются.

Баннер уведомляет об инструментах. «Принять» сохраняет выбор на 180 дней,
но не переинициализирует счётчики и не дублирует первый просмотр.
«Настройки cookies» ведут на /privacy#cookies. «Без аналитики» отключает
Метрику, Вебвизор, Calltouch, атрибуцию и передачу новых форм в Calltouch.
Отказ применяется к текущей странице, будущим переходам и перезагрузкам.
Доступные cookies/данные очищаются. После запуска стороннего кода отказ
перезагружает страницу, чтобы остановить контекст его выполнения.
Черновик сохраняется по прежним правилам, файлы нужно выбрать заново.
При недоступности localStorage выбор сохраняется в памяти и, если доступно,
в sessionStorage текущей вкладки. Если оба хранилища заблокированы, перенос
выбора через перезагрузку технически не гарантируется.

Это согласованное владельцем поведение продукта, не юридическое заключение
о достаточности уведомления для каждой цели обработки.

## Метрика и Вебвизор

Счётчик 113583806 работает в основном документе через metrika.js.
Скрытый iframe больше не используется: он не записывал взаимодействия
с родительской страницей. Старый /analytics-frame.html оставлен инертным
для совместимости с маршрутами и уже открытыми вкладками.

webvisor=true, clickmap=true, accurateTrackBounce=true. trackLinks=false:
клики на контакты учитываются только собственными событиями без текста контактов.
В кабинете нужно также включить Вебвизор и проверить запись реального посещения.
Форма заявки: ym-hide-content, ym-disable-keys, ym-disable-submit.
Корень редактора ОЛ: ym-hide-content, ym-disable-keys, включая нативный dialog.
Не добавлять ym-record-keys / ym-show-content внутрь этих областей.
Защита всей области скрывает также контактные значения, имена вложений,
ошибки с пользовательским текстом и восстановленные ответы.

Собственные просмотры сохраняют whitelist путей, допустимых UTM/yclid,
обрезанный referrer и ограниченные параметры событий. Vendor script работает
в основном документе и имеет доступ к контексту страницы; это не изоляция iframe.
lead_success отправляется после подтверждения API о сохранении, один раз
на submission_id (best-effort dedup); ошибка/неопределённый ответ не конверсия.
Достижение в реальном кабинете проверяется отдельно от наличия цели в настройках.

## Формы Calltouch

Frontend добавляет calltouch_tracking с enabled=true и проверенным session_id,
только пока отслеживание активно. Данные не входят в fingerprint отправки.
При отказе старые снимки недействительны; повтор с новым выбором не экспортирует
задним числом ранее сохранённые заявки. Блокировка скрипта не блокирует форму.
Серверная очередь описана в ../../backend/docs/calltouch-delivery.md.

Email-трекинг настраивается отдельно в кабинете через технический ящик.
Пароли почты не хранятся в frontend, репозитории или переменных Vite.

## Проверка

npm run lint; npm test; npm run test:prerender; production build с двумя флагами.
node scripts/analytics-browser.mjs и node scripts/cookie-banner-browser.mjs
используют Playwright (путь PLAYWRIGHT_MODULE, при необходимости CHROME_PATH).
Все публичные адреса перехвачены: настоящие заявки и запросы аналитики не создаются.
Проверить: автозапуск, один init/hit после «Принять», безопасные классы,
подтверждённый lead_success, передачу session_id, отказ и перезагрузку.
Внешнюю запись Вебвизора, подмену номеров и реальную доставку заявок проверяет
владелец совместно с подрядчиком после публикации согласованного релиза.
