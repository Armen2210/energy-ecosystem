# Доработки электронных ОЛ — 2026-11-01

Основа: `feature/ee-documents`, `2423008` (включая UTF-8 исправление).
Main, production, публичные документы и принятые снимки не изменялись.

1. **Числа.** Общий NumericInput использует integer/min из контракта: целые,
   точка/запятая и допустимый знак. Пустое значение и промежуточный знак/разделитель
   сохраняют нормальное редактирование. Неверная вставка отклоняется целиком с
   сообщением, без очистки символов и превращения в другое число. Проверены
   клавиатура, вставка, selected replacement/caret и fallback мобильного input.
   Старый ошибочный текст не исправляется молча; его можно удалить/заменить.
   Серверные пределы и exact source pair при смене единиц сохранены.
2. **Шевроны.** Использован существующий `faq__chevron`, без постоянных рамок;
   hit area 44 px, focus-visible и aria-expanded сохранены.
3. **Навигация.** На desktop SVG-стрелки с hover/focus/disabled; mobile — отдельный
   выбор раздела, затем Назад / счётчик / Далее. Проверены горизонтальный свайп,
   вертикальный жест, края экрана; исключения для полей и выделения сохранены.
4. **Сворачивание.** Выключение сворачивает, включение раскрывает. Шеврон меняет
   только раскрытие. Включённый свёрнутый ОЛ остаётся в отправке. Ответы и состояния
   восстанавливаются после reload; заполненный выключенный ОЛ остаётся в черновике.
5. **Карточки.** Компактные отступы и textarea, сводка и notice без потери статусов.
   Проверены 8 комбинаций главная/продукция × 1440×900/1366×768 × обычная/4 ОЛ.
   Высота формы примерно 483/552 px, верх под шапкой, низ внутри окна; на продукции
   края согласованы, тело ОЛ скроллится внутри. На mobile внутреннего вертикального
   скролла нет. При большом textarea и удвоенном тексте страница растёт, обязательные
   элементы не скрываются. На главной нет недоступного переключателя; chips ведут
   в редактор соответствующего товара, сохраняя все ОЛ.
6. **Товар.** topicPage обновляет направление при реальной смене товара и Back/Forward,
   но не при ререндере той же страницы. Reload сохраняет ручной выбор. Старый черновик
   без topicPage сохраняет ручной выбор при первом открытии. Контакты, File и ответы
   не сбрасываются. Submitting/indeterminate блокируют автоматическую смену и UUID.
7. **Отправка.** Реальные два включённых ОЛ ВНС/ПНС проверены в multipart, DB snapshots,
   expected_products/job и Linux worker. Одно локальное письмо: 2 PDF и synthetic.txt;
   тело перечисляет ПНС, ВНС. После сохранения подменён ответ на 502: повтор возвращает

8. **Кодировка/конфигурация.** Runtime read_text(encoding="utf-8") сохранён; fixture

## Ограничения и проверка заявки владельца

Использовались синтетические данные, Linux и локальный файловый/locmem email backend.
Реальный SMTP не использовался. База владельца недоступна; заявка №26 напрямую не
исследована. Потеря включённых ОЛ на текущем коде не воспроизведена; историческую
причину по одному уведомлению установить нельзя. Выключенные листы исключаются
намеренно. Несоответствие направления странице устранено отдельно.

Команда только чтения для владельца (из backend, с его действующими settings):

```sh
python manage.py shell -c "from apps.leads.models import Lead, QuestionnaireJob; l=Lead.objects.get(pk=26); print({'id':l.pk,'source_page':l.source_page,'direction':l.direction_slug,'sheets':list(l.questionnaires.values_list('product',flat=True)),'jobs':list(QuestionnaireJob.objects.filter(lead=l).values('status','expected_products','attempts','error_code'))})"
```

Она не читает ответы/контакты, не меняет данные и не отправляет почту.

## Воспроизведение browser проверок

`questionnaires-refinement-browser.mjs` требует QUESTIONNAIRE_TEST_ORIGIN и
QUESTIONNAIRE_TEST_API_ORIGIN (только loopback), включённые ОЛ и локальную почту.
`questionnaires-layout-browser.mjs` использует те же параметры, выполняет только GET.
Playwright/Chromium задаются PLAYWRIGHT_MODULE/CHROME_PATH; дополнительных зависимостей
в package.json не добавлено. Скриншоты с четырьмя ОЛ используют синтетический fixture.
