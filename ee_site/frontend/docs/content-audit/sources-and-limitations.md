## 4. Проверка локального содержания при первичном аудите

При первичном аудите на этой же кодовой базе с уже установленными React/Vite использован `createServer({root:process.cwd(), envDir:false, server:{middlewareMode:true}, appType:'custom'})`, затем `ssrLoadModule('/src/prerender/entry.jsx')` и `render(route)` для каждого `publicRoutes`.

- `VITE_EE_ANALYTICS_ENABLED=false`; `globalThis.fetch` заменён функцией, выбрасывающей ошибку. React-эффекты при SSR не выполняются.
- .env не читается; HTTP-сервер не слушает порт; POST/БД/SMTP и пользовательские хранилища не используются.
- Получены **19 HTML-фрагментов из текущего App** и его SEO collector. Проверены H1 и ссылки в main; title и description уникальны по 19 страницам.
- HTMLParser сравнил текст всех **48 FAQ answers** с `acceptedAnswer.text` в восьми FAQPage; совпадение полное. Это подтверждает согласованность, а не истинность ответа.
- Organization изучена отдельно в index.html: имя, URL, телефон, email и город/регион/страна совпадают с видимыми контактами. Юридическую актуальность и адрес производства не подтверждает.
- Сверены скрытые/неиспользуемые data-поля с CaseView и ProductPage/ServicePage. Наличие объекта в JS не приравнено к видимому блоку.
- Во время сверки просмотрены только публичные frontend-изображения hero.webp и обложка bmk-sports-complex. Первое показывает оборудование, второе — модуль на площадке. По изображению нельзя установить авторство, владельца производства, параметры или завершение испытаний. Все фотографии и метаданные не анализировались на предмет деанонимизации; это отдельная проверка перед публикацией.
- Временные материалы проверки: `/tmp/ee-content-audit-render/`, `/tmp/ee-content-audit-sources/results.json`. Это диагностические артефакты, не изменения сайта.

При первичном аудите не запускались npm ci/install, полноценный build, браузерный runner, API-тесты, Django, migrations или настройка сети. При текущем изменении только документации проверки приложения не повторяются; проверяются согласованность пяти документов, относительные ссылки, сохранность 19 страниц/48 вопросов, git diff --check и состав коммита. В текущем node_modules отсутствует parse5 из нового lockfile; это не дефект репозитория, а отличие ранее подготовленных зависимостей от PR №49. Зависимости оставлены без изменения по условиям аудита. Прежний dist не используется как доказательство актуальной версии.

Генератор `scripts/prerender.mjs` создаёт sitemap из `publicRoutes`: 19 маршрутов, без /contacts, /404, API/admin, служебного iframe и query/hash. Статического public/sitemap.xml после PR №49 нет. **Свежий итоговый sitemap и production sitemap в этом аудите не генерировались/не читались**; подтверждены реестр и алгоритм. ### Что обосновано уже сейчас

Конкретные исходные данные, границы договора, самостоятельные объяснения, реальные фотографии с контекстом и подтверждённые документы помогают посетителю выбрать решение и оценить поставщика. Это **редакторские и продуктовые рекомендации**, а не доказанные коэффициенты ранжирования. Обоснованность каждого изменения связана с наблюдением на странице в page-matrix.

Не установлен обязательный llms.txt, meta summary, специальный «AI FAQ» или уникальная структура для Алисы. Существующий AiSummary — обычный полезный HTML-блок; название компонента не даёт отдельного поискового преимущества. Meta summary в общей оболочке повторяет сайт целиком и не заменяет предметный description. Не предлагается увеличивать его роль или дублировать туда новый текст.

Разделять:
1. поисковое обнаружение/индексацию и выбор источника в поисковом ответе;
2. пользовательский запрос к ИИ, который может отдельно получать страницу;
3. сбор данных для обучения моделей.

Для каждого сервиса назначение и управление проверяются по его актуальной документации. Политику Google-Extended нельзя переносить на поисковые роботы Яндекса; ограничения обучения не следует считать общим способом управления цитированием.

## 7. Непроверенные предположения и ограничения

Нет Wordstat, Вебмастера, Search Console, Метрики, серверных журналов, публичной проверки Алисы или Search с ИИ. Группы запросов — гипотезы, не измеренный спрос; нет частотности, позиций, конкуренции, CTR, ROI или прогноза заявок. Сходство намерений ещё не доказывает каннибализацию: нужны запросы и показы по URL.

Спрос по аббревиатурам неоднозначен: ПНС у ЭЭ — **пожарные**, ВНС — **водопроводные** станции. Показатели сравнения давления/расхода, допустимые схемы и требования безопасности должны проверяться инженером. Предлагаемые поля опросников — вопросы для уточнения, а не объявленные возможности компании.

Поставка оборудования, монтаж и ПНР по России подтверждены владельцем (V5), с согласованием объёма/стоимости/условий в КП и договоре. Сервис, гарантия, применимость сертификатов, конкретные сроки и параметры исполнения не установлены. Четыре кейса БТП не свидетельствуют о четырёх типовых доступных сериях; длительность конкретного проекта не обещает срок изготовления нового изделия. Юридическая регистрация сама по себе не подтверждает годы производства.

Реальные .env, приватные вложения заявок, БД, SMTP и клиентские данные не читались. Только публичные data/изображения и документация. Существующее содержимое с географией не скопировано как новое разрешение на раскрытие заказчиков; для новой публикации нужен отдельный контроль конфиденциальности и прав.
