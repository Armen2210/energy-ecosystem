# Улучшить качество frontend, загрузку изображений и измерения взаимодействий

База PR: `main`. Ветка: `refactor/frontend-quality-performance`. Рекомендуемый статус: draft для проверки существующей истории ветки.

Исправляет лишние обновления frontend и очистку таймеров/асинхронных обработчиков; сохраняет поля и файлы формы при смене направления и состояние галереи при навигации. Прямой /contacts больше не показывает промежуточный footer-only кадр. Добавляет WebP/srcSet и резервирование размеров изображений без изменения CSS или зависимостей.

Добавлены воспроизводимые браузерные проверки и корректная привязка Event Timing/long tasks к действиям. Отчёты, Windows-инструкция и компактный архив JSON доступны в ee_site/frontend/docs/frontend-quality-review.zip (без PNG, dist и зависимостей).

Проверки: npm test 14/14, lint 0 ошибок/предупреждений, production build, diff --check, browser regression 53 checks и дополнительный fixture scope. Сохранённые builds сравнены парными сериями по 7 прогонов; tracing выделен отдельно. Mobile LCP БТП: 18.42 → 6.14 s; mobile CLS контактов: 0.48110 → 0.00011. Ухудшения также опубликованы: mobile cases LCP 7.19 → 7.61 s; desktop home simulated LCP 1.74 → 2.09 s. Desktop startup click→rAF closing 72.6 → 95.4 ms; дополнительный DOM-observer показывает удаление окна 21.1 → 18.5 ms. Эти показатели не называются полевым INP или завершённой отрисовкой.

История ветки: новый коммит 4823c08 меняет только ee_site/frontend. Ветка исходно основана на 86771f6 (PR #42), тогда как текущий main указывает на a135e76 (PR #37). Поэтому общий diff этого PR также содержит существовавшие до frontend-задачи коммиты PR #38–42, включая backend. Они не изменялись этим новым коммитом; учитывайте это при проверке базы PR.

Merge/deploy не выполнялись; production backend/БД/SMTP не использовались.
