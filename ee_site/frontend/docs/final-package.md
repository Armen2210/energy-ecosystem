## Загрузка JavaScript

Сравнение production build из одной среды, gzip одинаковым `node:zlib.gzipSync`.
Веса — байты, без HTTP-заголовков. Начальный HTML реально запрашивает два JS-файла;
56-байтные entry wrappers сборщика не включены в сумму: prerender их не подключает.

| JS | До, raw | До, gzip | После, raw | После, gzip |
| --- | ---: | ---: | ---: | ---: |
| main | 524 919 | 140 099 | 511 645 | 136 655 |
| policy | 3 550 | 1 640 | 3 550 | 1 640 |
| **Начальные запросы** | **528 469** | **141 739** | **515 195** | **138 295** |
| Отложенный QuestionnaireEditor | — | — | 12 448 | 4 703 |

Начальная экономия — 13 274 raw / 3 444 gzip. Это итог всего пакета, включая
новый индекс 27 фото; не только искусственный замер одного удалённого импорта.
Порог предупреждения Vite не повышен: предупреждение о main >500 kB остаётся.
Остальной сайт по-прежнему загружается прежним способом; общая маршрутизация не переделана.

Диагностика модулей исходной сборки (`renderedLength` сборщика, до окончательной
минификации; эти значения не являются отдельными gzip-файлами): editor 19 958,
NumericInput 2 352, numericInput 688; общий JSON-контракт 23 318, domain 5 278,
state 1 733, capabilities 1 179. Тяжёлый рендер полей и числовой компонент находятся
теперь в deferred chunk. Сводка/переключатель вынесены из editor в лёгкий
QuestionnaireControls; статических импортов editor из LeadForm/ProductPage больше нет.

**Контракт остаётся один и загружается сразу.** Его используют чтение sessionStorage,
проверка сохранённых единиц/source pair, сводка и серверная отправка через общий
валидатор/сериализатор. Удаление этой зависимости потребовало бы менять восстановление
или откладывать проверку включённых листов; копий/упрощённого валидатора не создавалось.
Стили ОЛ также остаются сразу для стабильного отображения сводки/переключателя.

Фактические JS-запросы:

- до: `policy-DuWXjjRp.js`, `main-BTDjzdtS.js`;
- после: `policy-DuWXjjRp.js`, `main-B-i9ZS08.js`;
- дополнительно `QuestionnaireEditor-CsToO-R2.js` при приближении блока к viewport
  (200 px) либо при восстановленном включённом ОЛ на странице продукта;
- на главной даже восстановленная сводка с двумя ОЛ не запрашивает editor.

Проверены задержка и отказ загрузки модуля. Показываются статус и ошибка с повтором,
общий store не очищается. Во время задержки можно менять общие поля. При отказе
валидные включённые ОЛ по-прежнему сериализуются; невалидные блокируют отправку
тем же валидатором. После синтетического 502 повтор имеет прежний UUID, оба ОЛ
и файл присутствуют в фактическом multipart. Повтор загрузки модуля может снова
завершиться ошибкой при недоступной сети/ассете; автоматического reload с потерей
File нет. Загрузка модуля не подтверждает отправку и не меняет submission_id.

## Проверки

- Frontend: lint, 56 unit tests; build 20 страниц + 404; 10 prerender/HTML tests.
- HTTP через настоящий nginx: 7 тестов (прямые адреса/статусы/canonical/sitemap,
  изоляция API/Admin, публичные документы и отсутствие новых редиректов).
- Backend: 131 тест — 130 passed, один PostgreSQL-only skipped в SQLite;
  отдельно PostgreSQL concurrency test passed.
- Production Chromium: desktop 1440×900, tablet 820×1180, mobile 390×844;
  каталоги, 27 фото, natural order, отсутствие горизонтальной прокрутки и увеличения,
  CTA, Back/Forward, JS-disabled links, hydration без pageerror.
- Задержка/ошибка module load; сводка на главной без editor; оба ОЛ, файл и прежний
  UUID в повторе после неопределённого ответа.
- Обычная форма: 20 групп lead-draft-browser на desktop/mobile; общий lock,
  контакты/File/черновик, смена товара, обработка ошибок, согласие и таймеры.
- Реальные browser unit-review и gateway-retry: точная величина после конвертаций,
  reload/ручного редактирования; сохранение → 502 → прежний UUID/ID/duplicate 200;
  изменение требует прежнего предупреждения. 429/неизвестный 409 не снимают неопределённость.
- Реальные два ОЛ + файл и отдельно четыре ОЛ: snapshots/job/ack. Linux worker для
  двух ОЛ: done, одно локальное письмо, два приватных PDF и synthetic.txt;
  повтор обработки/отправки не создаёт второго письма.
- git diff --check; оба принятых CSS и 14 публичных документов побайтно сохранены.

Проверки использовали синтетические данные, Linux, локальную файловую/locmem почту.
Реальный SMTP, hosting и deployment не использовались. Safari/iOS и физические
устройства не проверялись; мобильная проверка выполнена Chromium emulation.

Новые browser-проверки: `scripts/final-package-browser.mjs`. Требуются внешние
PLAYWRIGHT_MODULE/CHROME_PATH, FINAL_TEST_ORIGIN и FINAL_BEFORE_ORIGIN (только loopback),
исходная и текущая production-сборки. API — изолированный backend с локальной почтой.
HTML-проверки включены в `npm run test:prerender`, после `npm run build`.
