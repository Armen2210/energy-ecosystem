# Проверка замечаний после релиза — часть A

База: `363d4b97c11655282a901bf3aa7c61e57eadc990`; `origin/main` на момент проверки совпадал с ней. Проверен коммит черновика `d4b343c`, решения пересмотрены по ТЗ. Изменения Calltouch сюда не входят. Production, VPS, nginx, рабочие базы и счётчики не изменялись.

## Что изменено

- Баннер: на 360/390 px отказ слева, согласие справа; на десктопе сохранён порядок релиза. DOM/Tab совпадают с визуальным порядком. Тёплый `#9C3C0A` и холодный фон отказа сохранены, без смайликов. На 360–1440 px и при увеличении текста вдвое горизонтального переполнения не было. Механизм согласия не менялся. Исправлена устаревшая фраза о хранении черновика: ответы и контакты уже сохраняются в sessionStorage, файлы — нет.
- Сбой доступности ОЛ: сохранён повтор запроса из черновика. Chromium: abort первого capabilities-запроса → «Проверить снова» → редактор открывается; ответы, контакты и выбранный файл сохранены.
- Сбой JS-редактора: браузер кеширует отклонённый import; повтор того же import не является восстановлением. Вместо бесполезной кнопки предложено обновление с предупреждением о повторном выборе файлов/согласии и сроке черновика. При недоступном хранилище показано отдельное предупреждение. Chromium: abort chunk → обновление с доступным chunk → ответы и контакты восстановлены, файл нужно выбрать заново. Excel/PDF остаются доступны независимо от редактора; включённые ОЛ видны в составе и не исключаются из отправки. Валидация и проверка capabilities перед отправкой сохранены. При сбое можно явно исключить электронные ОЛ из отправки. Подтверждение выключает все ОЛ, сохраняя ответы, контакты и выбранные файлы. Если результат предыдущей отправки неизвестен, состав заявки менять нельзя.
- Excel/PDF: сами ссылки `#9C3C0A`, подчёркивание, явный focus outline и область высотой 44 px; «Или скачать» нейтральна. Контраст с белым фоном выше 6:1. URL и download-поведение не менялись.
- Документы: обычное начертание названий h3 только от 961 px. Категории, ссылки, цвет и мобильный вид сохранены. Все 14 файлов проверяет существующая suite.
- Короткие подсказки внутри восьми числовых полей всех четырёх ОЛ; пояснения остаются рядом после ввода. Подсказки не являются ответами и не задают расчётных чисел. Изменения подсказок вынесены из versioned JSON-контракта в renderer; обязательность, единицы и API не менялись.
- Счётчик обязательных полей: только [отдельный макет](required-count-mockup.html), без внедрения. ПНС: три применимых обязательных поля, при выборе жокей-насоса пять. Предусмотрена фиксированная ширина числа и отдельная строка на узком экране. Нужна приёмка макета до внедрения. Для будущей реализации отдельно учесть групповые требования БМК/БТП (они не сводятся к required=true).

## Что не воспроизведено

Галерея проверена в Chromium на 360, 390, 768, 1024, 1440 px, с задержкой WebP 250 мс и изменением layout viewport как при 125% zoom. У релиза изменение Y после догрузки ≤0,29 px, у варианта последовательных пар ≤0,60 px. Сдвигов рядов, нарушения порядка и обрезки не обнаружено. Неутверждённые пары из черновика отменены: сохранена раскладка релиза, все 27 фотографий, пропорции и отсутствие старого просмотрщика. CSS zoom/реальный OS scaling и устройства сотрудников не заменяются этим тестом.

Прокрутка: instrumented window.scrollTo при клике «Продукция» с `/` и `/about` — одна команда smooth, при prefers-reduced-motion одна instant. Перебивания второй командой не обнаружено, код оставлен без изменений. Browser Back выполнен в обоих сценариях. Возвраты кейсов/формы не переписывались; полный ручной прогон всех исторических entryScroll-сценариев не проводился.

## Загрузка: одинаковые условия, без заявления об ускорении

Node 24, Chromium, production build; локальный HTTP static server, одинаковые env: `VITE_API_BASE_URL=http://127.0.0.1:8000 VITE_EE_ANALYTICS_ENABLED=true`. Профили: без ограничений и CDP 100 мс latency / 750000 байт/с download / 250000 upload. По одному холодному/повторному открытию на маршрут/профиль; это диагностическая выборка, не статистический benchmark. Готовность кнопок оценивалась появлением клиентского баннера (после hydration), отдельно проверены настоящие клики меню/формы. В [сырых данных](evidence/a-results.json) есть HTML TTFB и timings/bytes каждого JS/CSS/изображения.

| Маршрут | Релиз холодный / повтор, мс | Ветка холодный / повтор, мс | Медленная сеть: релиз / ветка, холодный, мс |
|---|---:|---:|---:|
| `/` | 465 / 114 | 409 / 98 | 3100 / 3102 |
| `/about` | 283 / 78 | 246 / 72 | 2859 / 2043 |
| `/solutions/bmk` | 471 / 235 | 564 / 89 | 1767 / 1673 |

HTML TTFB в локальных замерах 1–19 мс. Ошибок JS/CSS/изображений нет. На странице изделия были CORS-ошибки capabilities: тестовый origin 8761/8762 отсутствует в разрешённых Django origins; это ограничение стенда, а не доказательство офисного сбоя. В тестах восстановления ответ capabilities явно подменён корректной заглушкой. После отмены пар галереи итоговый build повторён; цифры выше относятся к сравнению релиза с предварительной веткой, не выдаются за итоговый прирост. Масштабная переработка загрузки не проводилась.

Метрика проверена на production hostname, перенаправленном только на локальные файлы: до согласия/после отказа запросов нет; после согласия библиотека запрашивается; blocked/slow заглушки не мешают навигации. Отзыв удаляет iframe. Никаких обращений к настоящему счётчику: внешние запросы перехватывались/обрывались.

Для расследования офисного случая нужны время и точный URL, браузер/версия/ОС, масштаб, ширина окна, HAR с отключённым и включённым кешем (после удаления персональных данных), Console/Network, VPN/proxy/расширения и screenshot с номерами проблемных фото. DNS/TLS/офисный proxy/серверная задержка этой локальной проверкой не исключены.
