# Поиск и ИИ: фиксированный протокол повторной проверки

Подготовлен **03.11.2026, Europe/Moscow**, для release-readiness аудита `feature/ee-documents@8514af5d0bbf4f77176b804b0d2445385e0f5082`.

**Все внешние поисковые/ИИ-прогоны ниже пока НЕ ВЫПОЛНЕНЫ.** Нет доступного авторизованного поискового UI и выгрузок кабинетов; публичный сайт и справки блокируются прокси среды. Это сценарий владельцу, не перечень полученных ответов. Изменения robots, кабинетов и индексации не входят в аудит.

## Три раздельных объекта

1. Код в Git: локальная техническая/содержательная готовность новой версии — основной отчёт.
2. Опубликованный сайт: на дату запуска фиксировать доступный контент/дату, HTTP и фактическую видимость. Пока SHA сервера неизвестен, не приписывать ему изменения новой ветки.
3. После обновления: повторять на том же наборе после доказанного повторного обхода/индексации, отмечая даты каждого источника. Фиксированный срок попадания в ИИ не обещается.

## Сервисы, режимы и условия

| Сервис | Что выполнить при доступности | Что обязательно записать | Текущий статус |
|---|---|---|---|
| Яндекс Поиск с Алисой | Выбрать реально доступный режим ответа с поиском, не обычную SERP вместо ответа | Точное название режима в UI, URL сервиса, регион, наличие ссылок/поиска, вход в аккаунт, дата/время | не выполнено |
| ChatGPT | Новый диалог с включённым инструментом «Поиск», если доступен в аккаунте | Отображаемая модель/режим, явное включение веб-поиска, персонализация/memory, регион, дата/время | не выполнено |
| ГигаЧат | Только явно доступный режим с веб-поиском; если такого режима нет — отдельно обозначить ответ без веб-поиска | Точное название UI/режима, признаки использования веб-источников, аккаунт, дата/время | не выполнено |

Названия/доступность конкретных текущих режимов здесь не проверены. Если сервис требует отсутствующие доступ/авторизацию/подписку, записать **«не выполнено: причина»**, а не отсутствие компании в ответе. Не считать ответ режима без поиска подтверждением актуальной индексации или механизмов обучения. Дополнительные сервисы включать только с конкретным обоснованием и отдельной строкой условий.

Условия исходной серии: регион **Ростов-на-Дону** (если сервис позволяет), язык русский, обычный desktop browser, новая сессия/диалог для каждого запроса, без предыдущего контекста об Энергоэффекте. Если регион не выбирается — записать фактический/неизвестный, не приписывать Ростов. Персонализацию отключать только штатным доступным способом, не менять чужой аккаунт; если она действует, зафиксировать это. Авторизованность/платный тариф меняют условия, а не гарантируют качество.

1. Сначала завершить небрендовую серию N01–N14 во всех доступных сервисах; затем отдельно B15–B16. Один неизменённый prompt, без наводящего follow-up.
2. Сохранять share URL ответа, если доступен и не раскрывает личный чат; иначе компактный обезличенный скриншот/цитату с датой. Не публиковать персональные данные, идентификаторы аккаунта и приватную историю.
3. Ключевые N01, N04, N08, N13 повторить минимум ещё в двух новых диалогах того же режима; B15 повторить отдельно. Сравнивать вариативность, не присваивать «место» по одному ответу.
4. Если после выпуска нет подтверждения повторного обхода, помечать «обход новой версии не подтверждён». Повторить после подтверждения, сохранив прежние результаты; не перезаписывать исходный baseline.

## Как фиксировать каждый выполненный ответ

| Поле | Содержание |
|---|---|
| run_id, query_id, prompt | Стабильный ID, N/B ID, точный исходный текст |
| observed_at | Дата/время и timezone Europe/Moscow |
| service, ui_mode/model, web_search | Точные доступные сведения; yes/no/unknown |
| region, locale, account/personalization | Условия без идентификации человека |
| target_version | Published SHA, если известен; иначе «версия не установлена», отдельно проверенный Git SHA |
| company_mention | Да/нет; какое именно юридическое лицо названо |
| own_site_citation | Да/нет; точный URL цитаты/ссылки, не просто текст домена |
| third_party_source | Да/нет; конкретные внешние источники |
| accuracy | Верно/ошибка/не установлено; сверка конкретных изделий/услуг/контактов/фактов |
| direct_url_fetch | Отдельно для B16: получено актуальное содержание/получена ошибка/не установлено |
| evidence | Доступная ссылка или имя обезличенного снимка/цитаты |
| execution_status | Выполнено / не выполнено с причиной |

Упоминание компании без ссылки ≠ цитирование сайта; сторонний источник ≠ извлечение с собственного сайта; прямое чтение URL ≠ самостоятельное обнаружение. Не делать выводов о закрытом обучающем корпусе модели. Не складывать разные режимы/регионы/даты в один «процент видимости» без раздельных результатов и знаменателя реально выполненных запросов.

## Обычный поиск и кабинеты

- Снять исходные данные старой production-версии: **06.10–02.11.2026** против **08.09–05.10.2026**, одинаковые 28 дней, регион/устройство/тип поиска. Если экспорт не содержит нужной детализации, обозначить это.
- Яндекс Вебмастер: индексируемые/исключённые URL и причины, ошибки обхода, sitemap, запросы/посадочные/показы/клики/CTR.
- GSC: Page indexing, Sitemaps, Performance, selected canonical и последние crawl даты для главной/изделия/услуги/documents. Разделить брендовые/небрендовые запросы; не считать все варианты «Энергоэффект» одним юридическим лицом без проверки.
- Метрика дополняет переходами/обращениями, но не заменяет Search impressions и index coverage. Никаких сырых контактов/заявок в выгрузке.
- Выборочную SERP фиксировать с датой, регионом, устройством и персонализацией. `site:` — только наблюдение, не полный реестр индекса. В текущем аудите такая SERP не выполнялась.

## Доступ роботов и повторное измерение

Перед любым изменением правил читать актуальные первичные справки сервисов. На 03.11.2026 следующие обращения из среды заблокированы, чтение документации **не подтверждено**:

- OpenAI: <https://platform.openai.com/docs/bots>.
- Яндекс: <https://yandex.ru/support/webmaster/robot-workings/check-yandex-robots.html>.
- ГигаЧат: <https://developers.sber.ru/docs/ru/gigachat/overview> — точный документ о crawler/search выбирать по фактически используемому сервису, не по аналогии с другими.

Отдельно проверять роботов поиска, user-triggered retrieval и обучения, если поставщик их различает. Сверять текущие robots и HTTP/CDN/WAF; логи — только обезличенные и с разрешённым доступом. Тест с подставленным User-Agent не подтверждает доступ настоящего робота. Наличие или отсутствие `llms.txt` само по себе не устанавливает видимость. Изменения robots/allowlist в аудите не выполнять.

После публикации зафиксировать новый SHA/дату, реальные HTML/status/canonical/sitemap, подтверждённые даты crawl/index, затем повторить тот же протокол. Низкие показатели/отсутствие цитаты — материал для продвижения, а не автоматический технический блокер. Воспроизведённая блокировка нужных страниц или неверная информация оценивается отдельно по последствиям.
